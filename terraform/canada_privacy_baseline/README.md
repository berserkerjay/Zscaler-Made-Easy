## Use

```bash
terraform init
terraform plan -var 'assessor=Jane Doe' -out=tfplan   # review: creates, in-place updates, imports
terraform apply tfplan
```

Name the assessor first: every description this workspace pushes carries `[<assessor> pack …]`, and `assessor` is required (no default, never the tool's name), so `plan` and `apply` refuse without it. Pass `-var 'assessor=…'`, set it in `terraform.tfvars`, or export `TF_VAR_assessor`.

Credentials: `terraform.tfvars` (copy the example) or `ZSCALER_*` environment variables; nothing secret is in these files. The client needs a ZIA role with write access to DLP dictionaries, engines and the rule types in this pack.

Ordering: new rules are inserted starting at `rule_starting_order` and push existing rules down. Run `terraform apply -parallelism=1` if the tenant reports ordering conflicts.

`terraform destroy` removes exactly the objects in state, in dependency order.

## State and the lock file

Use a remote backend with locking for anything shared (the commented `backend "s3"` block in `terraform.tf`, or pass `-backend-config` on init). Commit `.terraform.lock.hcl` next to these files after the first `terraform init`; when the team runs Terraform on more than one operating system, record every platform's checksums once with `terraform providers lock -platform=linux_amd64 -platform=darwin_arm64 -platform=darwin_amd64 -platform=windows_amd64`. State, saved plans and `terraform.tfvars` carry tenant ids and, if you put them there, credentials: `.gitignore` keeps them out of git.

## Upgrading a workspace generated before 2026-09-29

Resource addresses are unchanged, so state carries over. Three things moved: `versions.tf` is now `terraform.tf` and `provider.tf` is `providers.tf` (delete the old two; the new ones replace them); the SaaS and email tenant ids that were one variable per rule (`saas_tenant_ids_<label>`) are now one map per channel, so move each value into `saas_tenant_ids = { "<rule name>" = [ids] }` (or `email_tenant_ids`), or set `saas_tenant_ids_default` for every rule at once; and `rule_starting_order` and `policy_rank` are validated (a whole number from 1, and from 0 to 7). An old per-rule value left in `terraform.tfvars` is only warned about, and the rule then stops `terraform plan` with a sentence naming it until the map holds its ids.

## Renaming a resource

A regenerated workspace keeps its labels, so state carries over. If you rename a resource by hand, keep its state with a `moved` block instead of destroying and recreating it:

```hcl
moved {
  from = zia_dlp_web_rules.old_label
  to   = zia_dlp_web_rules.new_label
}
```
