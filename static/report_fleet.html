Client Connector fleet

The enrolled devices and the profiles that govern them, together: which services really run, which devices Zscaler cannot see, how far behind the client is, which app profile is weakest, and what to fix first, ranked by the devices it affects. Read-only, and only when ZCC is in scope on the Scope page.

How it works

  1. Read the fleet. The app reads the Client Connector app and forwarding profiles and the hosted PAC files (the same paced reader the Path analyzer uses), then the enrolled devices and their per-device service status (ZIA, ZPA, ZDX). It takes a minute; Stop ends it at once.
  2. Read the alerts. Blind spots, bypass risk, ghost devices, registration anomalies, multi-device users and version drift, each with its exact definition beside it.
  3. Fix in order. The remediation plan ranks every gap by its impact times the devices it affects, with the fix in plain words. Export it as CSV, everything as one Excel workbook, or the page as a PDF report; tick counts only to leave every user and device name out (the PDF never names them).
  4. Watch it over time. Save each read to the history (counts only, kept on this computer) and compare any two reads: which versions came and went, and whether ZIA, ZPA and ZDX got better.

Device and user names are shown on this page because you need them to act; they are never written to a log, except that a one-time password request names its device (never the password) in the audit log. If the API client may not read devices, the page says so and shows the configuration only: never zeros as if the fleet were healthy.

No device permission? Import the portal's exports

In the Client Connector Portal, open Enrolled Devices and use Export to save Device Details and Service Status as CSV files (export both at the same time). Import one or both here: the page shows the same figures as a read, without the profile checks. Nothing is sent to a tenant, and the files stay in this app's memory.

DNS records for client hostnames

For ZPA client-to-client access: one DNS name per enrolled device (<hostname>.<domain>), sent to the client-to-client resolver you name. Built from the fleet read above, so read the fleet first. You get the text to download for Unbound, BIND (forward zones and a zone file) and a CSV of every name: the app sends nothing to any DNS server and applies nothing. Hostnames become valid DNS labels (letters, digits and '-'); renames, duplicates and collisions are listed.

Install command builder

Builds the Client Connector install command (MSI or EXE on Windows, the installer app on macOS) and a script to run next to the installer. Pick an app profile from the fleet read to fill in its policy token. Tokens and passwords show as ******** until you click Reveal; nothing is logged or saved.


      

      

        
One-time passwords for a device

        
For the help desk: a device's Client Connector one-time passwords (to uninstall it, turn a service off or exit it, as the tenant provides them). Only someone allowed to change the tenant may ask, with write mode on (as for a change to the tenant), ZCC ticked on the Scope page, the assessor's name and the confirmation typed. They are shown here once for 60 seconds and never kept: not logged, saved or cached. The audit log records who asked, when and for which device, never a password.

        

          
          
          
        

        

          
          
        

        

        

      

      

        
One device's details

        
Type a device id (UDID) from the Client Connector Portal to see which services run on it and whether they are healthy, its versions, strict enforcement, anti-tampering and device trust. Identifiers are hidden and the device's one-time passwords are never read into the answer. Reads only; needs ZCC ticked on the Scope page.

        

          
          
        

        

      

      

        
Why Client Connector was switched off

        
Counts from Client Connector's disable-reason report: per reason, device type and service, how many times it was switched off and by how many people. No user or device is listed. Reads only; needs ZCC ticked on the Scope page.
