Device posture

Device posture is defined in Client Connector and used twice: by ZPA access rules (posture conditions) and by ZIA rules (the device trust level Client Connector works out from a ZIA posture profile). This page shows each posture check, where it is defined, which devices it covers and every ZPA and ZIA rule that uses it, with the gaps. Fix the rules under Findings first, high before medium.

How it works
  1. Tick what you use on the Scope page: ZCC / Mobile Portal (where posture is defined), ZPA (access rules; give the ZPA customer ID too) and ZIA platform (rules that use the device trust level). Any one is enough; a product you leave out, or one that cannot be read, is shown as such.
  2. Read device posture. Each product is read once and shown live; Stop ends the read at once and keeps nothing.
  3. Read the findings, then Across products (each posture check, where it is defined, its platforms and every ZPA and ZIA rule using it), the posture profiles and the access rules in plain words. Export everything to Excel.
Read-only: nothing is written to the tenant. A list that could not be read is said so, never shown as empty.
