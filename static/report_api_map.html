Tenant API map

Which Zscaler features does this tenant have, and which of them can your API client read? This page finds out by asking: it reads each readable endpoint once, with GET only, and keeps the status, how many items came back and the names of the top-level fields. It never keeps a value, an id, a name or a secret. It is its own tool, not part of the licence and editions check, and its own action: you see every endpoint first and confirm. It reads only the products you ticked on the Scope page; the others are listed as skipped. Nothing is changed in your Zscaler.

How it works
  1. Choose what to map (everything readable, or only the endpoints that decide a feature), then click Map this tenant's APIs. It uses the tenant you are signed in to (or the sample tenant) and never asks for new credentials.
  2. Read the list and confirm. The page shows exactly which endpoints it will read, which it skips and why, and how long it takes. Nothing is sent until you confirm. Stop ends it at once.
  3. Read the answer. Each feature is present, not licensed or not enabled, no permission or an error, with the endpoint that decided it. The map is saved on this computer for this tenant, with the time.
Never read into this page: response values, ids, object names, passwords, key and token values, one-time passwords or exports. Endpoints that need an object id, or that return those, are skipped.
