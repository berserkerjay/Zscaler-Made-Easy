ZPA analysis

Reads the tenant's ZPA configuration once (app segments, segment and server groups, App Connectors, Private Service Edges, IdPs and every policy) and runs the ZPA analysis templates over it: unreachable access rules, segments nobody reaches, overlaps, over-broad domains and ports, bypasses, connector redundancy and more. The Diagnose tab then answers, for one user and one destination, which app segment matches, what serves it and which access rule decides.

This page counts the app segments, access rules and App Connectors of your ZPA, says in plain sentences which ones are broken and draws how they connect. Click Read ZPA and analyze, then click a sentence or a box in the map to see the objects behind it.

How it works
  1. Tick ZPA on the Scope page and give the ZPA customer ID with the API client (Connect to the tenant). Nothing is read otherwise.
  2. Read ZPA and analyze. The configuration is read once, list by list, paced and shown live; Stop ends the read at once and keeps nothing.
  3. Read the overview: plain sentences (how many segments nobody can reach, which connectors are down), the infrastructure map from users to App Connectors, and every object in tables you can narrow by clicking the map.
  4. Read the findings by template, filter by severity, export them as CSV, JSON or Excel. Each finding says in one sentence what is wrong and what to do.
Read-only: nothing is written to the tenant. A list that could not be read leaves its templates "not assessed", never "no finding".
