Custom NSS feed? Paste its feed output format

Copy it from the NSS feed in the ZIA Admin Portal (Feed Output Format), for example %s{time}\t%s{login}\t%s{url}\t%s{action}\t%s{urlcat}. Lines that are not JSON are then split by it. Leave it empty for JSON, a CSV with a header, or the default tab-separated format.

Privacy: the files are read by the app on this computer and analysed in memory; the lines themselves are thrown away and only counts are kept, in this server's memory, until you forget them or close the server. Downloads leave user names and addresses out unless you tick Include user names and addresses. Save report writes an owner-only file on this computer.

Read logs without uploading (optional)

Daily report from a folder

Off until you turn it on. Once a day, at the hour you pick, the app reads the log files in a folder on this computer that changed since the last report and saves one report. It only reads the folder: files are never changed, moved or deleted. Sub-folders, links and hidden files are skipped. The report is counts only unless you tick Keep user names.

Send reports to a share or host

Off until you turn it on. Sends a saved report (as CSV), or the staged DNS forwarder file, to an SFTP, SCP, SSH or SMB target. A target is used only if its host is in the allowed hosts. Passwords are kept in this computer's credential store, never in a file, and are not shown again. Needs the optional paramiko (SSH) or smbprotocol (SMB) package.

Syslog listener

Off until you start it, and it stops when you stop it or close the app. Point an NSS feed or LSS stream at it for a while, then analyse what arrived. It listens on this computer only (127.0.0.1) unless you type another address of this computer and tick Allow other computers. The lines stay in memory, are never written to disk, and are read as untrusted text.

What this page reads, and how it decides

Show the formats and the rules
  • ZPA Log Streaming Service (LSS) JSON: User Activity (each connection, its access rule, App Connector, Service Edge and internal reason), User Status (sign-ins and sessions), App Connector Status and Private Service Edge Status.
  • ZIA Nanolog Streaming Service (NSS) web, firewall and DNS feeds: JSON (one record per line, or the Cloud NSS HTTP shape with sourcetype and event), a CSV or TSV with a header row (NSS field names or the Insights column names), the default tab-separated format, or a custom format you paste.
  • A line no format reads is counted as malformed and skipped; nothing stops the analysis. Lines longer than 64 KB are skipped, and reading stops after 2,000,000 lines.
  • A failure is a ZPA connection whose internal reason is not a normal end. A spike is a time slot with at least 3 times the usual (median) count and at least 10. A user is named for many failures at 10 failures and half their connections, or 25 failures. New destinations are those first seen in the last day of the logs (the last quarter when they cover less than two days).
  • ZPA sessions: session IDs from User Status are put together per user. A session shorter than 5 seconds is a sign-in check and left out; sessions of the same user on the same day less than 60 seconds apart are one session (ZPA changes the session ID during a connection).
  • Times are shown as written in the logs; NSS writes them in the time zone set on the feed.
