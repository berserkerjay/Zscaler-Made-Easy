Migrate from another DLP

Turn another vendor's DLP policy export into disabled ZIA dictionaries, engines and web rules, through decisions a person reviewed. Nothing is inferred from the vendor's file beyond each policy's id and name; nothing is written to the tenant; every generated rule is DISABLED until change control enables it.

Review the decisions

  1. Click Download decisions template: it carries this export's SHA-256 and lists every policy with nothing approved.
  2. For every policy, either an approved web translation (action BLOCK / CONFIRM / ALLOW, one to four engine_refs, a unique order from 1, scope_acknowledged_any: true because the generated rule applies to Any user and location) or an approved retired / out_of_scope disposition with a reason.
  3. Spell out the dictionaries (phrases, patterns) and engines (a ZIA expression; {{dict:ID}} references a dictionary in the same file) and approve each one.
  4. Upload the reviewed file below and compile. Anything unmapped blocks the run and is listed as a question.

4. Compile the reviewed decisions

The same export is compiled again with these decisions; a changed export (different SHA-256) is refused until the decisions are reviewed.

5. Migration report

What happens next

Every generated web rule is DISABLED and applies to Any user and location. Hand main.tf.json to the platform team (or open the Terraform hand-off for the tenant's existing objects), run terraform init / validate / plan, apply in a test tenant, compare source and target incidents in monitor mode, then enable the rules one by one and order them with the tenant's existing policy. This page never contacts a tenant.
