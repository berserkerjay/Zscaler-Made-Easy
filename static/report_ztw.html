Cloud & Branch Connector

This page shows how workloads in public clouds and branches reach Zscaler through Cloud and Branch Connectors: the connector groups and their connectors, the forwarding rules that decide where workload traffic goes, the gateways, the connector locations, whether changes are activated, and who can change it. Click Read, then fix what says Fix first. Nothing is changed in your Zscaler.

How it works
  1. Tick Cloud & Branch Connector on the Scope page. It needs a OneAPI (ZIdentity) API client; the classic ZIA API sign-in cannot read it. Nothing else is read.
  2. Read. The page reads once, shown live as it reads. Stop ends the read at once.
  3. Fix the findings, Fix first, then Review: each says what was found, why it matters and how to fix it. Trace in the Path analyzer opens a workload trace with the connector group filled in, reusing this read.
Never read into this page: an API key's value, passwords, tokens and provisioning URLs. Admins are counted, not listed; location IP addresses and VPN credentials are counted, not listed.
