How it works
  1. Check coverage. It reads the SSL inspection rules and, when ZCC is in scope on the Scope page, the Client Connector profiles and PAC files. With ZIA Insights in scope it also asks how much HTTPS and HTTP traffic was inspected.
  2. Read the true coverage. One figure says how much web traffic Zscaler really saw inside: plain HTTP plus HTTPS it decrypted, out of all of it, by transactions and by bytes, adding up to 100%. Unknown traffic is never counted as inspected. Each share left encrypted is tied to the rule or bypass behind it. Without traffic numbers it is an estimate, and says so.
  3. Read the causes. Each thing that leaves traffic uninspected is listed with the rule or setting behind it and how risky it is. Leaving file sharing or AI tools encrypted is high risk; leaving banking or health sites encrypted for privacy is expected.
  4. Follow the recovery plan. The changes are ordered biggest risk first, each with where to change it and whether it is safe. Run it again afterwards to see the trend.
