Digest — the evaluation loop

When you click Run the loop now, the app re-reads the guidance sources and, for every tenant profile that remembers its secret, only what that profile's Scope page puts in scope: FP/TP detection ratio and the ticked packs' drift when DLP is in scope (on the DLP channels you run on Zscaler), the SaaS tenants when SaaS Security runs on Zscaler. A profile with nothing in scope is not read. It writes a digest. Every tenant read counts against the ZIA API rate limit, so nothing runs on its own: the timer is off unless the operator sets DLP_CHECK_CONTINUOUS_EVAL_HOURS (then it runs every that many hours while the server runs and stops when the server stops; for a schedule that survives the server, use Task Scheduler or cron as described below). It does not run the assessment checks or re-score the tenant (run the assessment for that). Nothing is written to any tenant.

Schedule and notifications

Settings live in local_settings.bat (or the environment): DLP_CHECK_SMTP_HOST, DLP_CHECK_SMTP_PORT, DLP_CHECK_SMTP_USER, DLP_CHECK_SMTP_PASSWORD, DLP_CHECK_DIGEST_FROM, DLP_CHECK_DIGEST_TO for e-mail (sent over STARTTLS with the mail server's certificate verified; trust a private CA with SSL_CERT_FILE, and the password is never sent without TLS); DLP_CHECK_DIGEST_WEBHOOK (an https Teams or Slack incoming webhook) for chat; DLP_CHECK_NOTIFY = noteworthy (default), always or never. Without the browser: RUN_Continuous_Evaluation.bat from Task Scheduler, or python continuous_eval.py --once from cron or the container.
