Change queue

Changes someone prepared but did not apply: a policy-pack deploy plan, a selective removal plan or a fix recipe, filed with Request approval in Deploy policy packs or Review & remediate, or a plan a scheduled sync job made (below). A writer other than the requester approves or rejects each one (four-eyes). An approved request is applied from here: the plan is checked against the tenant again first, and a request whose plan no longer matches is marked stale and nothing is written. Every step is in the audit log with who did it.

Scheduled sync

A sync job keeps rules of one or more target tenants in step with a source (a saved tenant profile or snapshot). Each run only reads: for every target it plans the adds, updates and (only if you ask) deletes, and files the plan here for another writer to approve. Nothing is applied until a named writer applies the approved request, through write mode and the typed confirmation; a plan whose target changed since is refused as stale. New rules are created disabled unless you say otherwise.
